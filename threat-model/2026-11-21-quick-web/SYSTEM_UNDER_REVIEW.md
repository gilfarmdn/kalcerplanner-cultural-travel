E01 — implementation observation. Locator: `src/middleware.ts:1-39`. Middleware verifies the `kp_session` JWT on every non-static route, clears invalid cookies and re-issues the cookie at most once per 60 s for active users within a 12 h absolute window. `/api/auth/*` is skipped.
E02 — implementation observation. Locator: `src/lib/session-token.ts:10-59`. HS256 JWT carrying id/name/email/loginAt; 45 min idle expiry; cookie `httpOnly`, `sameSite: lax`, `secure` only when `COOKIE_SECURE === "true"`; a hard-coded development secret is used only outside production; production throws if `AUTH_SECRET` is missing or <16 chars.
E03 — implementation observation. Locator: `src/lib/auth.ts:27-38`. `getUser()` re-reads role and `deactivatedAt` from the database on each call; deactivated or deleted users are treated as signed out.
E04 — implementation observation. Locator: `src/lib/api.ts:11-29`. `guard(roles?)` returns 401/403; `readBody` calls `req.json()` without checking Content-Type or Origin.
E05 — implementation observation. Locator: `src/app/api/auth/login/route.ts:11-52`. Per-IP limit 30/15 min is checked before parsing; per-email limit 10/15 min is checked before the password is verified (so failed and successful attempts both count). Same error for unknown email and wrong password; bcrypt runs for unknown email; unverified and deactivated accounts are rejected after the password check; redirect uses `safeNext`.
E06 — implementation observation. Locator: `src/app/api/auth/register/route.ts:13-58`. Rate limit is per IP only (10/h). When the email exists but is unverified, the route overwrites `name`, `passwordHash` and `role` of that account and sends a new verification email; a verified email returns 409 "Email sudah terdaftar".
E07 — implementation observation. Locators: `src/app/api/auth/verify-email/route.ts:9-27`, `src/lib/tokens.ts:5-35`. Tokens are 32 random bytes, stored as SHA-256 hash, single-use with atomic consumption; verifying marks the account verified without checking who set the current password.
E08 — implementation observation. Locator: `src/app/api/auth/reset-password/route.ts:10-34`. A valid reset token sets a new password, marks an unverified account verified and deletes other reset tokens. No code in the read files invalidates already-issued session JWTs.
E09 — implementation observation. Locator: `src/app/api/auth/forgot-password/route.ts:12-40`. Per-IP (10/h) and per-email (3/h) limits plus Turnstile; unknown email returns 404 with `EMAIL_NOT_FOUND` and a message saying the email is not registered.
E10 — implementation observation. Locator: `src/lib/rate-limit.ts:4-27`. Limiter is an in-process Map; the client key is the last `X-Forwarded-For` entry or the constant `unknown`; a comment names Tailscale Funnel as the trusted proxy.
E11 — implementation observation. Locator: `src/app/api/images/[id]/route.ts:4-22`. The route is excluded from the session middleware matcher.
